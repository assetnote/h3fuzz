# 100k RPS approach registry

[Performance documentation](README.md)

This is the live decision log for the 100k completed-response-RPS effort. It is
updated when an investigation, implementation, or benchmark changes the next
action. Performance claims remain provisional until the certification gates in
[`100k-rps-action-plan.md`](100k-rps-action-plan.md) pass.

## Status legend

- `queued`: evidence gathering has not completed.
- `testing`: an owner is actively gathering evidence.
- `accepted`: evidence supports keeping or implementing the approach.
- `rejected`: evidence falsified the hypothesis or the trade-off is invalid.
- `blocked`: a named external dependency prevents the next measurement.
- `complete`: the implementation and its acceptance evidence are retained.

These are hypothesis/approach states only. PERF work items use the binding
states `passed`, `infrastructure-blocked`, `hypothesis-disproved/skipped`, or
`failed` from the action plan; the two vocabularies are not interchangeable.

## Decision rules

1. Change one performance variable at a time and retain before/after artifacts.
2. Reject approaches contradicted by profiles instead of retaining speculative
   complexity.
3. Treat server saturation, UDP loss, accounting disagreement, non-zero final
   in-flight work, or protocol downgrade as an invalid performance point.
4. Do not turn the ordinary default path into an unsafe ceiling-test preset.
5. Do not publish a demonstrated-100k README claim until A08 is complete.
